# Glossarr

Форк [Gros-Jambon-Fr/Glossarr](https://github.com/Gros-Jambon-Fr/Glossarr) на базе upstream v1.3.0 — прокси перевода метаданных Sonarr с ограниченными повторами Skyhook и сохранением исходных полей при ошибках перевода. Лицензия MIT и авторство upstream сохранены.

[Полная английская версия / Full English README](README.md)

## Установка

Образ контейнера: `ghcr.io/vladido/glossarr:latest` ([GHCR](https://github.com/vladido/glossarr/pkgs/container/glossarr)).

Для фиксированной версии закрепите доступный тег `sha-<commit>` или digest; перед обновлением сохраните предыдущий digest.

Создайте отдельный каталог установки и сохраните следующий YAML как `docker-compose.yml` (полный пример из [docker-compose.yml](docker-compose.yml)):

```yaml
services:
  glossarr:
    image: ghcr.io/vladido/glossarr:latest
    container_name: glossarr
    restart: unless-stopped
    ports:
      - "443:3443"   # HTTPS — Sonarr traffic
      - "3000:3000"  # HTTP  — healthcheck
    env_file:
      - .env
    environment:
      - CERT_DIR=/certs
    volumes:
      - ./certs:/certs:ro
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:3000/health"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s
```

Compose использует обычную сеть проекта Docker, без внешней сети. Каталог `certs/` монтируется только для чтения; это единственное файловое состояние, которое нужно сохранить вместе с `.env`. Порты `443` и `3000` публикуются на всех интерфейсах хоста: ограничьте доступ firewall, особенно к HTTP-порту проверки состояния. Не добавляйте override `skyhook.sonarr.tv` в контейнер Glossarr — он должен обращаться к настоящему Skyhook.

Нужны Docker с Compose, Bash, curl, openssl и API-ключ выбранного источника. После сохранения Compose скачайте и просмотрите только скрипты сертификатов и доверия CA:

```sh
curl -fL https://raw.githubusercontent.com/vladido/glossarr/main/generate-certs.sh -o generate-certs.sh
curl -fL https://raw.githubusercontent.com/vladido/glossarr/main/trust-glossarr-ca.sh -o trust-glossarr-ca.sh
chmod 755 trust-glossarr-ca.sh
```

Просмотрите оба скрипта перед выполнением. Для воспроизводимости замените `main` на выбранный commit или тег в URL. Создание сертификатов заменяет существующие ключи: не запускайте скрипт повторно без резервной копии.

### 1. Создать TLS-сертификаты

Скрипт создаёт собственный CA и серверный сертификат для `skyhook.sonarr.tv`:

```bash
umask 077
bash generate-certs.sh
```

В каталоге `certs/` появятся:

| Файл | Назначение |
|---|---|
| `certs/ca.key` | Закрытый ключ CA; не подключайте к Sonarr |
| `certs/ca.crt` | Сертификат CA; подключите его к Sonarr для доверия Glossarr |
| `certs/server.crt` | Серверный сертификат Glossarr |
| `certs/server.key` | Закрытый ключ сервера |

> Сертификаты действуют 10 лет. Повторный запуск скрипта заменяет и CA, и серверный ключ: сначала сохраните защищённую копию, затем обновите доверенный CA в Sonarr. Создавайте сертификаты заранее: Compose монтирует `certs` только для чтения.

### 2. Настроить переменные окружения

```bash
umask 077
touch .env
chmod 600 .env
```

Укажите в `.env` свои значения; как минимум — API-ключи и язык:

```env
TVDB_API_KEY=your_tvdb_api_key
TMDB_API_KEY=your_tmdb_api_key
LANGUAGE=eng
```

Все варианты приведены в разделе [Конфигурация](#конфигурация).

### 3. Запустить Glossarr

```bash
docker compose config --quiet
docker compose pull
docker compose up -d
```

Glossarr слушает:
- Порт `3000` — HTTP (проверка работоспособности).
- Порт хоста `443` → порт контейнера `3443` — HTTPS, трафик Sonarr. Прилагаемый Compose не задаёт `GLOSSARR_PORT`; оставьте значение `3443`, пока сохраняется mapping `443:3443`.

### 4. Подключить Sonarr

Добавьте в `docker-compose.yml` Sonarr:

```yaml
extra_hosts:
  - "skyhook.sonarr.tv:<your_host_ip>"
volumes:
  - /path/to/glossarr/certs/ca.crt:/custom-cont-init.d/glossarr-ca.crt:ro
  - /path/to/glossarr/trust-glossarr-ca.sh:/custom-cont-init.d/trust-glossarr-ca.sh:ro
```

Замените `<your_host_ip>` IP-адресом хоста Glossarr (где открыт порт 443). После изменения Compose пересоздайте только Sonarr:

```bash
docker compose up -d --force-recreate sonarr
```

Теперь запросы Sonarr к Skyhook проходят через Glossarr.

> **Примечание:** Механизм `custom-cont-init.d` поддерживается образом [linuxserver/sonarr](https://docs.linuxserver.io/images/docker-sonarr/). Для другого образа настройте доверие к CA по его документации.

> **Порт 443 занят:** Если его уже использует, например, обратный прокси, см. [TCP-проброс](#дополнительно-tcp-проброс).


## Отличия от upstream v1.3.0

- **Ограниченные повторы Skyhook:** поиск и карточка сериала выполняют до трёх попыток, с таймаутом 5 секунд на попытку и паузами 250/500 мс. В upstream эти запросы выполняются один раз без этого таймаута. Контракт не распространяется на остальные проксируемые маршруты или все внешние API перевода.
- **Оригинальный ответ при общей ошибке перевода:** после успешного ответа Skyhook сохраняется исходный JSON. Если обработка перевода карточки или результатов поиска выбрасывает ошибку, Sonarr получает этот исходный ответ с HTTP 200, а не HTTP 502. Если сам Skyhook недоступен, HTTP 502 сохраняется.
- **Изоляция сезонов и эпизодов:** ошибка перевода отдельного элемента сохраняет его исходные поля, не отменяя переведённые поля сериала и успешных соседних элементов. Ошибки разрешения TMDB ID и списка сезонов TVDB также обрабатываются отдельно, позволяя сохранить оригинальные поля без остановки всего ответа.

Переводы TVDB/TMDB, режимы полей, поддержка AniList/Kitsu и схема TLS/DNS унаследованы от upstream, а не являются новыми возможностями этого форка. Он не является новым upstream-релизом Glossarr; лицензия MIT и авторство upstream сохранены. Инструкции ниже описывают общие возможности и конфигурацию.

## Возможности

- Перевод **сериалов**, **сезонов** и **эпизодов** (названия и описания).
- Источники перевода **TVDB** и **TMDB**, с автоматическим резервным источником для каждого поля.
- Настройка каждого поля: `always`, `never` или `native` (переводить, только если оригинальный язык сериала совпадает с выбранным).
- Параллельная загрузка из TVDB и TMDB и объединение по отдельным полям.
- **Поддержка аниме** через [AniList](https://anilist.co) и/или [Kitsu](https://kitsu.io): отдельные источники с собственным языком, автоматическое распознавание по таблице соответствий [anime-lists](https://github.com/Fribb/anime-lists).
- Нет npm-зависимостей; требуется Node.js 20 или новее.
- Прозрачная передача запросов ко всем прочим маршрутам Skyhook.

## Интерфейс и границы работы

Glossarr — HTTP(S)-прокси, а не веб-приложение: собственного GUI или страницы настроек нет. `logo.png` — логотип, не снимок интерфейса. Настройки задаются через окружение; результат виден в метаданных Sonarr после обновления сериала. Прокси не переводит медиафайлы, субтитры или аудио и не управляет загрузками.

Нет npm-зависимостей, но остаются зависимости от Node.js, контейнерного образа, TLS и внешних API. Сохраняйте API-ключи и закрытые ключи вне Git; выдавайте Sonarr доверие только к предназначенному для этого CA.

## Принцип работы

Sonarr обращается к `skyhook.sonarr.tv` по HTTPS за метаданными. Glossarr перехватывает этот трафик следующим образом:

1. Подменяет разрешение DNS для `skyhook.sonarr.tv` внутри контейнера Sonarr (через `extra_hosts`).
2. Предоставляет TLS-интерфейс с серверным сертификатом, подписанным собственным центром сертификации (CA).
3. Настраивает доверие Sonarr к этому CA.

Затем Glossarr передаёт запрос настоящему Skyhook, дополняет ответ переводами и прозрачно возвращает его.

## Требования

- Docker и Docker Compose.
- Бесплатный [API-ключ TVDB](https://thetvdb.com/api-information), если используется TVDB.
- Бесплатный [TMDB Read Access Token](https://www.themoviedb.org/settings/api), если используется TMDB.
- `openssl` для создания TLS-сертификатов.

## Поддержка аниме

Glossarr автоматически определяет аниме по таблице [Fribb/anime-lists](https://github.com/Fribb/anime-lists) — проекту сообщества, сопоставляющему ID TVDB с AniList, Kitsu, AniDB, MAL и другими сервисами. Заслуга создания таблицы принадлежит её участникам.

Для аниме вместо TVDB/TMDB могут использоваться отдельные источники:

- **[AniList](https://anilist.co)** — бесплатно, без API-ключа, английский и японский языки.
- **[Kitsu](https://kitsu.io)** — бесплатно, без API-ключа, английский и японский языки.

Оба источника запрашиваются на уровне сериала. Для сезонов и эпизодов по-прежнему используются TVDB/TMDB (AniList и Kitsu не предоставляют переводов отдельных эпизодов), но с языком аниме.

**Порядок резервных источников для названия и описания аниме:**

1. `ANIME_PRIMARY_SOURCE` на языке `ANIME_LANGUAGE`.
2. `ANIME_SECONDARY_SOURCE` на языке `ANIME_LANGUAGE`.
3. TVDB/TMDB на языке `LANGUAGE` (общий резерв).
4. Доступные значения AniList/Kitsu по умолчанию (английский). Если источник недоступен или не вернул значение, сохраняется поле Skyhook.

> Если `ANIME_PRIMARY_SOURCE` и `ANIME_SECONDARY_SOURCE` не заданы, все сериалы, включая аниме, используют обычные источники `PRIMARY`/`SECONDARY`; обнаружение аниме не влияет на результат.

Таблица аниме загружается с GitHub при запуске контейнера и кэшируется в памяти. Для её обновления перезапустите контейнер.

## Конфигурация

Настройка выполняется через переменные окружения контейнера Glossarr.

### API-ключи

| Переменная | Когда требуется | Назначение |
|---|---|---|
| `TVDB_API_KEY` | При использовании TVDB | API-ключ TVDB v4 |
| `TMDB_API_KEY` | При использовании TMDB | TMDB Read Access Token |

### Язык

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LANGUAGE` | `fra` | Целевой язык по ISO 639-2 (`fra`, `eng`, `spa`, `deu`, `ita`, `jpn`, `kor`…) |

### Источники перевода

| Переменная | По умолчанию | Значения | Назначение |
|---|---|---|---|
| `PRIMARY_TRANSLATION_SOURCE` | `tvdb` | `tvdb`, `tmdb` | Основной источник переводов |
| `SECONDARY_TRANSLATION_SOURCE` | _(не задан)_ | `tvdb`, `tmdb` | Резервный источник, если в основном отсутствует поле |

Если заданы оба источника, Glossarr запрашивает их параллельно и объединяет по полям: название и описание выбираются независимо.

### Режимы перевода

Каждое поле настраивается отдельно:

| Переменная | По умолчанию | Поле |
|---|---|---|
| `SHOW_TITLE_MODE` | `native` | Название сериала |
| `SHOW_OVERVIEW_MODE` | `always` | Описание сериала |
| `SEASON_TITLE_MODE` | `native` | Название сезона |
| `SEASON_OVERVIEW_MODE` | `always` | Описание сезона |
| `EPISODE_TITLE_MODE` | `native` | Название эпизода |
| `EPISODE_OVERVIEW_MODE` | `always` | Описание эпизода |

Доступные режимы:

| Режим | Поведение |
|---|---|
| `always` | Всегда заменять переводом |
| `never` | Никогда не заменять: оставить исходное значение Skyhook |
| `native` | Заменять, только если оригинальный язык сериала совпадает с заданным `LANGUAGE` |

> **Пример:** При `LANGUAGE=fra` и `SHOW_TITLE_MODE=native` французский сериал *Les Revenants* получит переведённое название, а *Breaking Bad* сохранит оригинальное.

### Источники аниме

Glossarr распознаёт аниме по загружаемой при старте таблице [Fribb/anime-lists](https://github.com/Fribb/anime-lists) и может направлять его на отдельные источники [AniList](https://anilist.co) и/или [Kitsu](https://kitsu.io) вместо TVDB/TMDB. Оба бесплатны и не требуют API-ключа.

| Переменная | По умолчанию | Значения | Назначение |
|---|---|---|---|
| `ANIME_PRIMARY_SOURCE` | _(не задан)_ | `anilist`, `kitsu` | Основной источник перевода аниме |
| `ANIME_SECONDARY_SOURCE` | _(не задан)_ | `anilist`, `kitsu` | Резервный источник, если в основном нет поля |
| `ANIME_LANGUAGE` | _(используется `LANGUAGE`)_ | `eng`, `jpn` | Язык источников аниме. AniList и Kitsu поддерживают только английский и японский; для остальных языков Glossarr автоматически возвращается к TVDB/TMDB. |

**Как это работает:**

- Сериал считается аниме, если его ID TVDB присутствует в таблице anime-lists.
- Для аниме источники и язык `ANIME_*` используются для **всех полей** (сериал, сезоны, эпизоды).
- Если AniList/Kitsu не поддерживают `ANIME_LANGUAGE` (например, `fra`), они ничего не возвращают, и Glossarr обращается к TVDB/TMDB с общим `LANGUAGE`.
- Если источники аниме не настроены, для всех сериалов используются обычные `PRIMARY`/`SECONDARY`.
- При наличии используются резервные данные AniList/Kitsu; пустые значения и ошибки не должны стирать исходные поля Skyhook.

> **Пример:** При `LANGUAGE=fra`, `ANIME_PRIMARY_SOURCE=anilist`, `ANIME_LANGUAGE=eng` обычные сериалы получают французские метаданные TVDB/TMDB, а аниме — английские метаданные AniList.

### TLS

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CERT_DIR` | _(не задан)_ | Путь внутри контейнера к каталогу с `server.crt` и `server.key`. Автоматически задаётся в прилагаемом `docker-compose.yml`. |
| `GLOSSARR_PORT` | `3443` | HTTPS-порт Glossarr. Установите `443`, чтобы открыть Glossarr непосредственно на стандартном HTTPS-порту (если обратный прокси не нужен). |

## Проверка результата и диагностика

```sh
curl http://127.0.0.1:3000/health
docker compose logs --tail 100 glossarr
```

Node.js 20+ включён в образ. Установка Node.js или npm-зависимостей на хост не требуется. `/health` проверяет процесс и сообщает конфигурацию; он **не** проверяет доступность Skyhook/TVDB/TMDB или фактический перевод.

В Sonarr откройте существующий сериал и выполните обновление метаданных. Сверьте отдельно название/описание сериала, сезона и эпизода; сообщение `processed` в логах не доказывает изменение поля. Это действие обновляет метаданные Sonarr, поэтому сначала выберите подходящий сериал.

| Симптом | Что проверить |
|---|---|
| Ошибка TLS в Sonarr | DNS `extra_hosts`, адрес/порт Glossarr, SAN `skyhook.sonarr.tv` и установленный CA |
| Нет перевода, запрос успешен | Наличие перевода в выбранном источнике, mapping ID, `LANGUAGE` и режимы полей |
| `502` | Доступность настоящего Skyhook; подробности в логах |
| Ошибка одного сезона/эпизода | Этот элемент сохраняет исходные поля; остальные могут перевестись |
| После смены `.env` ничего не изменилось | Пересоздайте Glossarr: обычный restart не перечитывает окружение из Compose |

Для маршрутов поиска и карточки сериала Skyhook запрашивается до трёх раз, с таймаутом 5 секунд на попытку и паузами 250/500 мс. Эти параметры заданы в коде, переменных окружения для них нет. Прочие маршруты передаются отдельным catch-all запросом; указанный retry-контракт к ним не относится. При общей ошибке перевода возвращается исходный ответ Skyhook; при ошибке отдельного элемента сохраняется этот элемент.

## Обновление, откат и резервная копия

Загрузите готовый образ: `docker compose pull`, затем `docker compose up -d`. Проверьте `/health`, TLS из Sonarr и результат обновления метаданных. Для отката закрепите предыдущий тег/дайджест, сохранив настройки и CA. Для полного отключения прокси сначала удалите override `skyhook.sonarr.tv` из конфигурации Sonarr и пересоздайте Sonarr, затем остановите Glossarr; иначе запросы метаданных останутся направленными на остановленный прокси.

Сохраняйте защищённую копию `.env`, Compose и `certs/`, включая закрытый `ca.key`. Не публикуйте их в Git. Собственной базы данных нет; таблица аниме кэшируется в памяти.


## Дополнительно: TCP-проброс

Если порт 443 занят, например Traefik или nginx, настройте обратный прокси для прямой передачи TCP-трафика `skyhook.sonarr.tv` на HTTPS-порт Glossarr без завершения TLS.

**Пример для Traefik** (`dynamic.yml`):

```yaml
tcp:
  routers:
    skyhook:
      entryPoints:
        - websecure
      rule: HostSNI(`skyhook.sonarr.tv`)
      service: skyhook
      tls:
        passthrough: true
  services:
    skyhook:
      loadBalancer:
        servers:
          - address: glossarr:3443
```

В этом случае удалите `ports: ["443:3443"]` из `docker-compose.yml` Glossarr и убедитесь, что Glossarr находится в одной сети Docker с Traefik.
